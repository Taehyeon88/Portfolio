1. 전체 구조

"프롬프트를 잘 쓴다"가 아니라, 세션이 새로 시작돼도 같은 품질로 일하도록 컨텍스트를 파일로 고정하는 방식입니다. 기획은 Claude Docs, 코드 규칙은 repo 문서, 반복 절차는 커맨드로 역할을 나눴습니다.

2. 사례: /perk 검푸른 망토 한 건이 처리되는 과정

유물 하나를 추가하는 일을 예로 듭니다. 입력은 한 줄이고, 그 뒤의 절차는 커맨드가 문서를 읽어 따릅니다. 첫 사례였던 "검푸른 망토"(아군 깃발에 대한 적 용병의 공격이 빗나감, 전투당 1번)는 howto 문서에 "검증된 절차"로 남아 있습니다.

/perk 검푸른 망토, 아군 깃발에 대한 적 용병의 공격이 빗나갑니다. 전투당 1번 발동됩니다.
  1. 입력 검증. "언제(조건)"와 "무엇을(효과)"을 구분할 수 없으면 코드를 쓰지 않고 먼저 질문합니다.
  2. 읽기 순서 고정. 유물 카탈로그 → howto 전체 → 재사용 후보 클래스는 파일을 직접 읽기 → 규약과 관련 GameAction의 Performer. 카탈로그와 실제 파일이 어긋나면 어느 쪽이 낡았는지 먼저 알립니다.
  3. 분해와 재사용 판단. 설명을 조건/효과로 나누고 각각 재사용 / 수치만 다름 / 신규로 분류합니다. 없을 때만 새로 만듭니다.
  4. 멈춤 조건. 모호한 범위·타이밍·수치, 부분 겹침, 새 GameAction 필요, 기존 계약(시그니처·Performer) 수정 필요 중 하나라도 걸리면 선택지를 제시하고 승인을 받습니다.
  5. 생성. 클래스를 작성하고, 에셋은 Unity MCP로 ScriptableObject를 만듭니다.
  6. 문서 갱신과 검증. 카탈로그를 갱신하고 콘솔을 읽어 에러 0을 확인합니다.
절차 자체는 이 파일에 복제하지 않는다 — 문서가 기준이다. 아래는 이 커맨드 고유 규칙만 적는다. 비어 있거나 "언제(조건)"와 "무엇을(효과)"을 구분할 수 없으면 코드를 쓰지 않고 AskUserQuestion으로 먼저 묻는다. 추측하지 않는다.— .claude/commands/perk.md 발췌

왜 이렇게 설계했나

  • 절차를 한 곳에만 둡니다. 커맨드는 문서를 가리키기만 하므로, 규칙이 바뀌면 문서 하나만 고치면 됩니다.
  • 재사용을 기본값으로 합니다. 비슷한 유물이 쌓일수록 AI가 중복 클래스를 만들기 쉬워서, 카탈로그 대조를 첫 단계에 고정했습니다.
  • 허용 도구를 제한합니다. 커맨드마다 쓸 수 있는 도구를 명시하고, 점검용 /convention은 모델이 자동 호출하지 못하게 했습니다.

3. 가드레일과, 실패에서 만든 규칙

AI가 틀릴 수 있다는 전제로 규칙을 CLAUDE.md에 명문화했습니다. 아래는 그중 실제 운영 중인 것들입니다.

규칙의도
코드를 짜기 전에 의도를 한 줄로 먼저 말한다잘못된 방향이면 코드가 나오기 전에 끊을 수 있게 합니다.
명세와 충돌하면 차이를 먼저 알리고 진행한다조용한 변경을 막습니다.
문서와 코드가 어긋나면 어느 쪽이 낡았는지 짚는다. 조용히 맞추지 않는다문서가 현재 코드를 역추출한 스냅샷이라, 낡았을 수도 "알려진 위반"일 수도 있기 때문입니다.
모르는 것은 추측하지 않고 (원작 확인 필요)로 표기한다원작 규칙을 그럴듯하게 지어내는 것을 막습니다.
핵심 인프라(ActionSystem, Singleton<T>)는 수정하지 않고 상속·사용만 한다전체 시스템이 얹힌 기반이 조용히 깨지는 것을 막습니다.
에디터 작업은 클릭 순서를 안내하고 멈춘다AI가 한 척하지 않게 하고, 작업 분담을 분명히 합니다.

① 허락 없이 구현한 사건

특성 작업에서 계획을 승인받은 직후 AI가 여러 파일을 바로 수정했고, 제가 중단시켰습니다. 이후 "승인된 계획이 있어도 구현 단계마다 어떤 파일을 바꿀지 알리고 허락을 받는다"를 규칙으로 기록했습니다.

4. 코드 전에 충돌부터 정리하는 진행 방식

기획이 "로그라이크 → 스테이지 클리어형"으로 바뀌었을 때, 곧바로 코딩하지 않고 task-list의 첫 항목(T-00)에서 기획서와 현재 코드가 어긋나는 6곳을 표로 만들었습니다. 이후 작업은 "T-xx 진행해" 한 줄로 명령하고, 각 항목은 해당 챕터 명세 1개와 convention만 읽고 시작합니다.

#기획서현재 코드
C1로그라이크 없음, 실패 시 같은 스테이지 재도전런 단위 진행·"처음부터" 시작 로직
C4덱 = 스테이지 기본 영웅 + 선택 영웅 (5~8장)런 동안 누적되는 덱
C6클리어 보상 = 휘장·별·해금용병 후보 제시, 소문 획득, 엘리트 스테이지

표는 6건 중 3건만 발췌했습니다. 결정이 필요한 항목은 각 문서에 (결정 필요)로 남겨 두고 임의로 정하지 않았습니다.

5. 한계와 아직 못 한 것

  • 효과를 수치로 측정하지 못했습니다. 시간 단축률이나 버그 감소율 같은 비교 자료는 없습니다. 위의 숫자는 모두 구조의 크기이지 성과가 아닙니다.
  • 문서 유지 비용이 있습니다. convention.md는 현재 코드를 조사해 만든 스냅샷이라, 규약에서 벗어난 기존 코드가 11절에 "알려진 위반"으로 남아 있습니다. 문서와 코드의 정합은 아직 사람이 점검합니다.
  • 커맨드가 만든 것과 손으로 만든 것을 구분해 집계하지 않았습니다. 그래서 에셋 개수 같은 수치를 AI 성과로 내세우지 않았습니다.
  • 환경 의존이 있습니다. 일부 규칙(Serena 호출, 단계별 허락 등)은 개인 작업 메모리에 있고 repo에는 없습니다.
